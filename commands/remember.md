把用户给出的信息存入持久记忆。参数：$ARGUMENTS

用户明确要求记住 = L0 层，立即写入、永久生效（status: active），frontmatter 的 `evidence` 直接引用用户原话。

## 第一步：确定级别（严格按此顺序）

1. 用户话里带 **全局 / 所有项目 / 以后都 / 一律** → `user`
2. 用户话里带 **这个项目 / 当前项目 / 本项目 / 这个仓库** → `project`
3. 用户话里带 **本机 / 这台电脑 / 我这台机器** → `local`
4. 都没带 → 按内容判断：换台电脑或换个项目依然成立 → `user`；依赖具体代码库 → `project`；依赖这台机器 → `local`
5. 拿不准 → 默认 `project`（有当前工作区时），否则 `user`

## 第二步：落盘

1. **先查重**：Read 该级别目录下的 `MEMORY.md`，同类条目已存在就改写原主题文件并更新那一行索引，绝不追加矛盾条目。
2. project/local：目录为 `~/.kimi-code/memory/<scope>/<工作区key>/`（key = 工作区绝对路径中非 `[a-zA-Z0-9_-]` 字符替换为 `-`），目录不存在则创建，并写 `meta.json` 的 `{"workspace":"<绝对路径>"}`。
3. 写主题文件，frontmatter：`title / scope / origin: manual / status: active / type（偏好|事实|坑）/ evidence（用户原话）/ created / updated`（project/local 另含 workspace）。
4. 索引追加/更新一行 `- [标题](文件.md) — ≤80字钩子`。若注入带"⚠ 接近上限"警告，先合并/精简旧条目再新增。
5. 绝不把密钥/token/密码写入记忆。明显临时性的信息要先说明并确认，不要默默照写。
6. 若注入头部有"用户曾删除过以下自动记忆"清单，同类内容先向用户确认再写。

## 第三步：告知（必须）

回复最后一行固定格式：`💾 已沉淀：《标题》→ 级别`（手动记忆不带"试用"）。用户纠正级别时立即迁移文件并更新索引，再告知一次。
